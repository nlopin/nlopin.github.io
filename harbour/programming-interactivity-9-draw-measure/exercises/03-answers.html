The sales log

Original ↗Fixed ↗⤓ Download fixed

What the recording shows

One long task per keystroke. Yellow: render → row builds a row for every one of the 87 554 matches, and topItems (≈ 80 ms at 1×) runs at the end of every render. Purple: style and layout of all those rows, in the same task. Then pre-paint and paint in a second task.

The hypothesis

Build and lay out only the rows that are visible, not all the matches. Compute "Top items" once: it doesn't depend on the search.

The change

  • topItems() runs once at start-up; render reuses the result.
  • The list scrolls inside its own box. A spacer as tall as all the rows (visible.length × 32 px) gives the right scrollbar.
  • On every scroll, renderWindow works out which rows are in view from scrollTop / 32, renders only those, and moves them into place with transform.
  • A new search scrolls back to the top.

Takings bars

Original ↗Fixed ↗⤓ Download fixed

What the recording shows

One long task per click, mostly purple: about a thousand Layout events inside render's call stack, each one forced by reading offsetWidth. JavaScript and paint are small.

The hypothesis

The loop reads offsetWidth right after the previous iteration changed a width, so the browser lays out the page 1 000 times. Read the width once, before the loop.

The change

  • The track width is read once, before the loop. Every bar has the same track width, so the result is identical.
  • The loop now only writes: one layout at the end of the frame instead of 1 000 forced ones.

Find a dish

Original ↗Fixed ↗⤓ Download fixed

What the recording shows

One long yellow task per keystroke, almost no layout or paint. Bottom-Up: fuzzyScore has most of the self time (≈ 80%), then search.

The hypothesis

fuzzyScore runs on all 100 000 dishes, word by word, on every keystroke. The dishes share a small vocabulary: score each distinct word once per query, and look the scores up.

The change

  • Each dish keeps its text split into words once, at start-up (dish.words).
  • search keeps a Map from word to score for the current query: about 150 distinct words get scored instead of ≈ 2.5 million.
  • A dish's score is still the best score among its words, so the matches and their order are unchanged.
