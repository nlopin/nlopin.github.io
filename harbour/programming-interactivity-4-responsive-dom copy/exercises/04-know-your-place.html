A card that knows its place

Media queries ask the window. A component doesn't live in the window: it lives in a slot, and the same card can sit in a wide column or a narrow sidebar on the same page. Container queries let it ask the slot.

Two elements, two jobs. The wrapper is the container (container-type: inline-size). The component inside asks it (@container (width >= …)). The blue labels show each slot's width.

1

A card that knows its place

The same card is perfect in the wide column and cramped in the sidebar. A media query can't tell them apart: it only knows the window.

Two steps. ① Make every .slot a query container (container-type: inline-size). ② In an @container query: when the slot is at least 26rem wide, lay the card out with the picture on the left (a grid: 10rem 1fr). Then press 🖥 1200 and ▭ 700 and watch the sidebar card.

Why it works

The query asks the nearest ancestor that is a container. That's the killer pattern: a wrapper (.slot) is the container, the component inside (.card) asks it. The card can't be its own container: a box that changes its layout because of its own width could change its width again, forever.

.slot {
  container-type: inline-size;
}
@container (width >= 26rem) {
  .card {
    display: grid;
    grid-template-columns: 10rem 1fr;
    gap: 1rem;
    align-items: start;
  }
  .pic { margin: 0; }
}

An important note: why is it 0px wide?

The stamp is squashed into a tower of single words.

Someone made the stamp's wrapper a container so the stamp could adapt. Read the blue size label on .stamp-slot. A container's width is not allowed to depend on its content (otherwise: the loop again). An inline-block gets its width only from its content. So it gets… nothing. Give the container a width that comes from outside.

Solution

container-type: inline-size applies size containment on the inline axis: for sizing, the box pretends it's empty. Anything shrink-to-fit (inline-block, a float, an absolute box, a flex item with no basis, a max-content track) collapses. Fix it by giving the container a width that comes from its parent.

.stamp-slot {
  display: block;          /* fills its parent */
  container-type: inline-size;
}
/* or keep inline-block and set a width: width: 16rem; */
3 · bonus

Container units

Container queries come with units: 1cqi is 1% of the container's inline size (its width). Make the card title fluid relative to its slot: clamp(1.1rem, 0.6rem + 4cqi, 2.2rem) (a rem part again, so zoom still works). The main card's title should end up bigger than the sidebar's, at the same window width.

Solution
.card h3 {
  font-size: clamp(1.1rem, 0.6rem + 4cqi, 2.2rem);
}
4 · bonus

Feature queries

A card that has a .badge inside should get a red border: .vendor-card:has(.badge). Wrap it in @supports selector(:has(*)), so a browser that doesn't understand :has() skips it cleanly. Outside the block, give sold-out cards a dimmer title for everyone.

Solution

@supports (property: value) tests a declaration; @supports selector(…) tests a selector. Where support is missing, the block is skipped: no half-applied rules. Today every modern browser has :has(); the pattern matters for the next new thing (right now: animation-timeline, anchor positioning).

@supports selector(:has(*)) {
  .vendor-card:has(.badge) {
    border-color: #ff6b4a;
  }
}
