Act 2 · Fluid

Fluid market

Breakpoints make the page jump between a few fixed designs. Fluid values slide between a minimum and a maximum instead, and need no breakpoints at all. The checks measure at 360, 800 and 1280px at once.

Three functions do it all. min(a, b): the smaller one. max(a, b): the bigger one. clamp(min, preferred, max): the preferred value, held between the two limits. Keep the fluid calculator open in a tab.

1

A headline that grows

The headline is fine on a phone and fine on a laptop, and it jumps in between.

Replace the jump with a slide: 2.5rem at a 360px window, 6rem at 1280px, and a straight line between. Get the numbers from the fluid calculator (or work them out: two points make a line). The middle value needs a fixed part, or zoom stops working; make it rem, so it also follows the reader's font-size setting.

Why it works

A line through (360, 40) and (1280, 96) rises 56px over 920px: 6.087px per 100px of window, so 6.087vw. At 360px that part is 21.9px; the rest, 18.1px, is the fixed part: 1.13rem. clamp() then stops the line at both ends.

h1 {
  font-size: clamp(2.5rem, 1.13rem + 6.087vw, 6rem);
}
2

One fluid gutter

On a phone the padding eats the screen; on a big monitor everything is cramped against the edges.

Make one custom property, --gutter, that slides from 1rem on a phone to 3rem on a big screen, with clamp(). Use it for the section's side padding and the list's gap.

Solution

Spacing is where fluid values shine: nobody notices a padding growing smoothly, everybody notices one that jumps.

:root {
  --gutter: clamp(1rem, 0.22rem + 3.48vw, 3rem);
}
.block { padding-inline: var(--gutter); }
.vendor-list { gap: var(--gutter); }
3

A column that fits everywhere

The text column is 40rem wide. On a phone that's wider than the phone.

One line, no media query: the column is 40rem wide, but never wider than the window minus 1rem on each side. Centre it. min() picks the smaller of two sizes, and inside it you can do maths without calc().

Why it works

min(100% - 2rem, 40rem): whichever is smaller wins. On a phone, the first one; on a laptop, the second. margin-inline: auto centres a block with a width (last lecture). Inside min(), max() and clamp() you can add and subtract directly.

main {
  width: min(100% - 2rem, 40rem);
  margin-inline: auto;
}
4

The hero on a phone

On my phone the “Get a free ticket” button is hidden behind the browser's bottom bar.

On a phone, 100vh is the height with the address bar hidden: taller than what you see when the page loads. svh is the small viewport: always visible. Make the hero fill the small viewport minus the 4rem header.

Why it works

Three new viewport units: svh (small: bars visible), lvh (large: bars hidden, what vh always was) and dvh (dynamic: changes while you scroll, so things can jump). For a hero, svh is the calm choice. The live preview is a desktop iframe, where all three are the same: test this one on a real phone.

.hero {
  min-height: calc(100svh - 4rem);
}
5 · bonus

Variable fragments

Each category should have its own colour, used three times: the tag's text, the card's border and a soft glow. Store only the hue in a variable, --hue, and build the colours from it: hsl(var(--hue) 80% 65%). Food is 30, music 200, crafts 120. Then each category needs one line.

Solution

A variable doesn't have to be a whole value. --hue: 30 is just a number; it becomes a colour only inside hsl(). The same trick works for sizes: --n: 3 and calc(var(--n) * 1rem).

.vendor-card {
  --hue: 0;
  border-color: hsl(var(--hue) 80% 65%);
  box-shadow: 0 0 1.5rem hsl(var(--hue) 80% 65% / 0.25);
}
.vendor-card .tag { color: hsl(var(--hue) 80% 65%); }
.food   { --hue: 30; }
.music  { --hue: 200; }
.crafts { --hue: 120; }
