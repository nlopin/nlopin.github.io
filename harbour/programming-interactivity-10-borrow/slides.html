Content delivery network

A CDN keeps copies of files on servers near the users

browserasks for a URL
nearby
edge serverone of many, in many cities
(points of presence)
only on a miss
originthe server with the original file
  • Cache hit: the edge has a copy and answers itself.
  • Cache miss: the edge fetches from the origin, answers, and keeps a copy.
  • DNS points the hostname at the CDN, and the request reaches a nearby edge.
  • The origin decides how long copies may be kept: the Cache-Control header.

~0:02. Why it matters: latency is mostly distance, and every request pays at least one round trip; a nearby edge makes that trip short. The origin also gets only the misses, not every request. Large CDNs: Cloudflare, Fastly, Akamai, Amazon CloudFront. How a request finds a nearby edge depends on the CDN: some answer DNS with a nearby server's address, Cloudflare announces the same addresses from every location (anycast) and the network routes to the closest. It's not only for libraries: this course's pages on GitHub Pages are served through Fastly, and the Lecture 8 API (harbour-api.lopin.me) runs on Cloudflare's network.

DevTools → Network → a request → Headers

lopin.me · GitHub Pages

               s-maxage=31536000, immutable

  • Standard HTTP: Cache-Control (who may keep a copy, and for how long: max-age in seconds), Age (seconds this copy has been in the cache: here 86 days).
  • Vendor headers: x-cache, x-served-by (Fastly), cf-cache-status (Cloudflare): hit or miss, and which edge answered.

~0:03. Both captured with curl -I while writing this deck; run it again and the values change. The left one: GitHub Pages behind Fastly (Varnish is Fastly's cache software); TOJ is the code of the Fastly location that answered (Madrid), and it didn't have a copy yet. The right one: jsDelivr's file came from Cloudflare's edge, which had held it for 86 days. max-age=31536000 is one year; s-maxage is the same limit for shared caches like a CDN; immutable tells the browser not to even revalidate. A CDN can promise that only for URLs whose content never changes: that's why the version is in the URL.

What you take on

Code you didn't write, from a server you don't run

it can be down

The CDN, a bad network, a company firewall.

it can change

A new version with a different API, if you didn't pin one.

it can be big

Hundreds of kilobytes to parse before your first line runs.

it can be hostile

A compromised package runs with all the rights of your page.

it sees your visitors

CDNs for open-source packages

Package CDNs serve the npm registry as URLs

https://schemecdn.jsdelivr.nethost/npm/registryd3package@7.9.0version/+esmfile · build
  • npm is the registry where JavaScript packages are published. Millions of them.
  • jsDelivr, unpkg, esm.sh fetch packages from the npm registry (their origin) and serve any file in them through a CDN. (cdnjs hosts a curated list instead.)
  • Remove the file part and jsDelivr lists every file in the package: cdn.jsdelivr.net/npm/d3@7.9.0/

~0:06. jsDelivr's /+esm and esm.sh convert a package to an ES module on the fly, rewriting its own imports into more CDN URLs. d3@7.9.0/+esm is a 1.5 kB file that imports 30 more: look at it in the Network panel.

Way 1 · the oldest

<script src>: the library becomes a global

  • The file is a UMD build: it puts one global on window (L, Chart, d3).
  • Order matters: the library's tag before yours.
  • Globals share one namespace with your scripts: a library's d3 and your own d3 variable, and one silently hides or overwrites the other.
  • Some libraries need their CSS too.

~0:07. Still the most common snippet in READMEs, and still fine for a single library. defer on both tags keeps the order and doesn't block parsing.

Way 2 · ES modules

Import from a URL, in a module

  • No globals: the names exist in this module only (Lecture 5).
  • Named { formatHex }, default confetti, namespace * as d3: which one works depends on what the package exports. The README says.
  • Only inside type="module".
Uncaught SyntaxError: Cannot use import statement outside a module

~0:08. The error appears when the script tag lacks type="module". If a default import gives undefined or "does not provide an export named default", try the namespace import and log it: console.log(d3) shows what's inside. The @4 on culori is on purpose: the Versions slide shows why it should be exact.

Way 3 · what the docs show

Bare names fail in the browser

Uncaught TypeError: Failed to resolve module specifier "d3". Relative references must start with either "/", "./", or "../".

"d3" is a bare specifier: a package name, not a URL. Node and bundlers know where npm packages live (node_modules). The browser only knows URLs.

~0:09. Nearly every README and nearly every AI answer writes imports this way, because nearly every project has a build step. Firefox's message: "The specifier “d3” was a bare specifier, but was not remapped to anything." Two ways out: replace the name with the URL in every file, or tell the browser once: the import map.

One place for every dependency

An import map: names to URLs

  • Every module on the page can now import … from "d3", as the docs write it.
  • Every version in one file. Upgrading is one line.
  • It must come before the module scripts that use it.
  • A URL or a local path: the code doesn't care which.
  • JSON loads as a module too: static data, no loading state, no error handling.

~0:10. Supported everywhere since 2023. The second entry previews vendoring (slide "Vendor it"): switching from CDN to a local copy changes the map, not the code. A trailing-slash entry ("lodash/": "https://…/lodash-es@4.17.21/") maps a whole folder, for packages imported by path. JSON modules (import attributes): Chrome 123, Safari 17.2, Firefox 138, so in every major browser since 2025. The file loads before the importing module runs; if it fails, the whole module fails. The server must send Content-Type: application/json, and like every module it needs http://, not file://. Fine for fixed data shipped with the code (config, a word list); data that can fail or change goes through fetch. Exercise 1 can use either for its snapshot; the stretch's live Overpass query needs fetch.

~0:11. CommonJS is Node's original module format; plenty of packages still ship only that. The CDN converters handle it. If the library throws process is not defined, it expects Node or a bundler (process.env.NODE_ENV): try the CDN's converted build, or find another. A .cjs file from jsDelivr isn't even run: Chrome refuses its MIME type, application/node.

Look before you choose

What a dependency costs, in two panels

network

Filter by JS, disable cache, reload. How many requests did one import start? How many kB transferred? One converted module can import dozens more (d3@7.9.0/+esm: 30): a waterfall.

performance

Record and reload. Compile and Evaluate (Script or Module) in yellow: what the library costs on the main thread before your code runs.

A 500 kB library to format one date is a bad trade. Intl.DateTimeFormat is free.

~0:12. This ties back to Lecture 9's Measure act. Sizes, minified and gzipped (measured): Leaflet 1.9.4 42 kB, Chart.js 4.4.1 69 kB, D3 7.9.0 92 kB, three.js 0.170 171 kB. Pay later

Load a library when it's needed, not with the page

  • import() is an expression: it returns a promise for the module, and the download starts at the call.
  • Works in classic scripts too, with the same URLs and import map names.
  • The cost moves from page load to the first click: show a loading state (Lecture 8).
  • <link rel="modulepreload" href="…"> fetches and parses a module early, without running it.

~0:13. Static import declarations are hoisted and must all load before the module runs; import() runs when the line runs. The same module is fetched and evaluated once: a second import("leaflet") resolves from the module map. modulepreload is the fix for the waterfall from the previous slide: list the deep dependencies in the HTML and they download in parallel instead of one level at a time. Leaflet's ESM build in 1.9.4 is unminified: 425 kB on disk. A fair candidate for loading on demand.

When a browser doesn't have it

A transpiler rewrites syntax. A polyfill adds a missing API.

fixesexamplewho does it
transpilersyntax an old engine can't parsea ?? b → a != null ? a : bTypeScript, esbuild, Babel, by target
polyfillan object or method that doesn't existTemporal, URLPatternyou, or Babel + core-js

~0:14. TypeScript never adds polyfills: its lib setting only changes which types it believes exist, and target only lowers syntax. Vite and esbuild lower syntax to build.target and add no API polyfills either (Vite's one exception is a small modulepreload polyfill); @vitejs/plugin-legacy or Babel's preset-env with core-js add them based on a browser list. Still used? Much less than in the IE years: evergreen browsers ship most things within months. The remaining use is a new API that some browsers lack: Temporal shipped in Firefox 139 and Chrome 144; check Safari's status before class. Load it conditionally, as here, so browsers that have it pay nothing. The polyfill.io takeover on the Security slide was a polyfill CDN. temporal-polyfill 1.0.5 is MIT-licensed and the version current when this deck was written.

What the browsers ship

How to know what the platform has, this month

  • Baseline: newly available means every major browser has it; widely available means for 30 months. The badge is on every MDN page.
  • webstatus.dev: search a feature, see which browsers ship it and when.
  • web.dev/blog: a monthly "New to the web platform in …" post. One page, all browsers.
  • Release notes: Chrome (developer.chrome.com/release-notes), Firefox (MDN · Firefox releases), Safari (webkit.org/blog).
  • The next ones: the Interop dashboard (wpt.fyi/interop) for what all browsers are fixing this year; tc39/proposals for JavaScript, by stage.

~0:16. Baseline is maintained by the W3C WebDX community group from MDN's browser-compat-data; "major browsers" means Chrome, Edge, Firefox and Safari, desktop and mobile. The monthly web.dev post is the cheapest habit: ten minutes a month. A TC39 proposal reaches Stage 4 when it's in two shipping engines; Stage 3 is when engines start implementing. Linters can check it for you: browserslist accepts a Baseline query, and @eslint/css has a use-baseline rule. Lint rules come back in Act 2.

~0:17. Semver is a promise, not a guarantee: minors occasionally break things too. A pinned +esm URL keeps the version, not the bytes: jsDelivr generates those files and may rebuild them. Static files (dist/d3.min.js) never change, and only those work with the integrity hashes on the Security slide; jsDelivr itself says not to use them on generated files.

Trap · the code is from another era

The AI's code was right, for D3 v3

Uncaught TypeError: Cannot read properties of undefined (reading 'linear')
  • d3.scale.linear() is D3 v3. Since v4 (2016) it's d3.scaleLinear(). Models learned from years of old examples.
  • Compare the version the code assumes with the version you load. Ask for the version explicitly.
  • Big jumps have a migration guide or a CHANGELOG.md. Read the one for your major.

~0:18. Same family: Chart.js v2 options in a v4 project, Leaflet plugins for 0.7, three.js examples using Geometry (removed in r125). The fix is cheap if you recognise it: the error says "undefined", meaning the namespace exists but not that member.

Trap · the package that isn't

Check that the package exists, and is the one you think

  • Models sometimes invent plausible package names.
  • People register those names and publish malware into them (slopsquatting). Typos work too (typosquatting).
  • Before you add one: the npm page. A linked repository, weekly downloads, the last publish date, the maintainers.
two minutes

npmjs.com/package/name → repository → stars, issues, last commit. A package with 12 downloads and no repository is not your chart library.

~0:19. This matters more in projects with npm, where npm install runs install scripts on your machine. In a browser page the damage is limited to the page, which leads to the next slide.

Security

A library runs with all of your page's rights

It can read the DOM and localStorage, send fetch requests, log keystrokes. There's no sandbox between your code and theirs.

Subresource integrity: the browser refuses the file if a single byte changed.

~0:20. Libraries often publish the hash with their install snippet (Leaflet's download page does); or compute it: openssl dgst -sha384 -binary leaflet.js | openssl base64 -A. Works on <script> and <link rel="stylesheet">; import maps have an integrity section in newer browsers. Pin first: a hash for a moving version breaks on the next release. In 2024 the polyfill.io CDN was taken over and served malware to every site still loading it: the case for integrity, and for vendoring.

~0:21. event-stream (November 2018): about 2 million weekly downloads; the new maintainer added a dependency, flatmap-stream, whose encrypted payload ran only inside the Copay wallet's build. ua-parser-js (October 2021): about 7 million weekly downloads; three malicious versions were live for about four hours. colors and faker (January 2022): protestware by their own author, Marak Squires. polyfill.io (June 2024): a Chinese company bought the domain and the GitHub account in February; the CDN then served redirects to mobile users. chalk, debug (8 September 2025): the maintainer clicked a link from npmjs.help; the 18 packages had about 2.6 billion weekly downloads together; the payload hooked fetch and wallet APIs in the browser; removed within about two hours. Shai-Hulud (September 2025, again in November): a postinstall script searched the machine for npm and GitHub tokens, published the secrets to public GitHub repositories, and republished every package the stolen npm token could publish, with itself inside. Hundreds of packages. Most of these were found within hours, which is the argument for the next slide's waiting period.

Supply chain

Fewer chances to be hit, less damage when you are

  • Fewer dependencies. Each one is code and people you trust. The platform first.
  • Pin and lock. Exact versions, a committed lockfile, npm ci. A bad release arrives only when you update.
  • Wait before updating. Most are caught within days: a minimum release age (pnpm), a cooldown (Dependabot).
  • No install scripts. --ignore-scripts; pnpm 10 runs only the ones you allow.
  • In the browser. Vendored files or SRI; a Content-Security-Policy that limits where data can go.

~0:22. pnpm: minimumReleaseAge in minutes (since 10.16); Yarn 4 has npmMinimalAgeGate; Dependabot: cooldown in dependabot.yml. A lockfile pins the whole tree, transitive dependencies included, which is what ^7.9.0 in package.json doesn't. pnpm 10 doesn't run dependencies' lifecycle scripts unless they're listed in onlyBuiltDependencies. CSP connect-src 'self' blocks fetch to an attacker's server; it doesn't stop everything (an image request can still carry data), so it reduces damage rather than preventing it. Trusted publishing: npm accepts releases from a GitHub Actions or GitLab workflow via OIDC, so there's no token on a laptop to steal, and releases carry provenance. If you publish packages yourself: 2FA with a security key, and trusted publishing instead of tokens. A security key resists phishing; a code from an authenticator app can be typed into a fake site, as in the chalk case.

Privacy

Every request to a CDN tells it who is visiting your page

  • The request carries the visitor's IP address, User-Agent and, usually, your page's URL in Referer.
  • Under the GDPR an IP address is personal data. Sending it to a third party needs a legal basis, such as consent.
  • January 2022, Regional Court of Munich: a site that loaded Google Fonts from Google's servers owed a visitor €100 in damages.
  • The fix is the next slide: serve the files yourself, fonts included.

~0:22. LG München I, 20 January 2022, 3 O 17493/20. It was followed by a wave of warning letters to German site owners. This deck does it too: open the Network panel on these slides and filter by fonts.g. The old argument for shared CDNs ("the file is already in the visitor's cache from another site") no longer holds: since 2020–21 Chrome, Firefox and Safari partition the HTTP cache by the top-level site, so a copy cached on one site isn't reused on another.

Borrowing has terms

familyexamplesyou mustyour code

⚠ Copyleft: a work that includes the code must be released under the same licence.

~0:24. JavaScript sent to a browser is distributed, so a GPL library in a page makes the page's own scripts GPL too. Copyleft is sometimes called "viral". Weak copyleft: the obligation applies when you distribute the page, to the people you distribute it to, and only to the library's own files (MPL-2.0) or the library itself (LGPL); unchanged files need only the notice, and for JS the shipped file is already the source. Weak copyleft is file-level for MPL-2.0; LGPL's "linking" rule was written for C and is unclear for bundled JS, so companies often treat it like GPL. Apache-2.0 adds an explicit patent licence and asks you to keep its NOTICE file. No licence is not "free to use": copyright applies by default. Not legal advice; companies have a list of approved licences, and tools like license-checker read every dependency's licence field.

Code, data, fonts, tiles

Each borrowed file has its own terms

where it's written

license in package.json, the LICENSE file, the npm page. Keep LICENSE next to the vendored copy.

data

OpenStreetMap is ODbL. Showing it: credit "© OpenStreetMap contributors". Publishing a dataset made from it: that dataset is ODbL too, copyleft for data.

fonts

Most open fonts are under the SIL Open Font License: use, embed and self-host freely, but don't sell the font itself.

services

Tile servers and APIs have usage policies, not licences. OSM's tiles: identify your app, no heavy use, no bulk downloads.

source-available

Readable on GitHub is not open source. Highcharts is free only for non-commercial use.

licences change

Mapbox GL JS was BSD until v2 (2020), then proprietary. Its v1 lives on as the fork MapLibre GL.

~0:26. Leaflet is BSD-2-Clause: keep the copyright notice. The ODbL's share-alike applies to derived databases (OSM data plus your own corrections, published as a dataset); a map image or an app that only displays the data is a "produced work" and needs only the attribution. A licence change applies to new versions: Mapbox GL JS v1.13 stays BSD, which is what made the MapLibre fork possible. Same story elsewhere: Elasticsearch, Redis, Terraform moved to source-available licences and were forked (OpenSearch, Valkey, OpenTofu).

npm and a bundler

What npm and a bundler add

  • npm install d3: into node_modules, exact version in the lockfile. Commit the lockfile.
  • ^7.9.0: any 7.x from 7.9.0. ~7.9.0: only 7.9.x.
  • A build tool like Vite (bundling with Rollup and esbuild): dev server, bare names, TypeScript, minifying, dropping unused code.

~0:28. One slide so the words are familiar. A page with an import map and no build step is a complete, deployable project; a bundler earns its place when there are many dependencies, TypeScript, or a lot of code to split and minify.

Leaflet 1.9.4 · BSD-2-Clause

A map: a library, tiles from a server, data from OpenStreetMap

  • Leaflet draws the map and handles drag and zoom. Its CSS and its images/ folder are part of it.
  • Tiles: 256 px images, one URL per zoom level z and grid cell x, y. Data from a server, not code.
  • Coordinates are [latitude, longitude], in degrees.
  • a.distanceTo(b) on a LatLng: metres, on a sphere.

~0:29. The ESM build exports named functions (map, tileLayer, marker, latLng) and doesn't create window.L; plugins written for the global break with it. In 1.9.4 it's unminified (425 kB) and ends with a sourceMappingURL comment: DevTools fetches the .map file from the CDN too. The CSS is required: without it the map is grey with tiles scattered down the page. The default marker icon URL is resolved relative to the CSS, so from a CDN it just works; a vendored copy needs the images/ folder next to the CSS. The tiles need the network either way. Order is latitude first in Leaflet; GeoJSON stores longitude first: the most common map bug.

A platform API · navigator.geolocation

Where is the user?

  • Callbacks, not a promise: an API from 2010. accuracy is a radius in metres.
  • Secure context only: HTTPS or localhost. On plain HTTP it doesn't exist.
  • The first call asks for permission. Call it from a click, not on page load.
  • On a laptop the position comes from nearby Wi-Fi networks: accuracy can be tens of metres or several kilometres.
  • watchPosition calls back on every move, until clearWatch.

~0:30. A prompt on page load gets denied by reflex, and browsers now hide or auto-block prompts that aren't tied to a user action. enableHighAccuracy: true asks for GPS on phones: slower and more battery. maximumAge lets the browser answer from a cached position. On macOS the browser itself also needs permission in System Settings → Privacy & Security → Location Services, or every call fails with code 2.

Permissions

The prompt has a Block button. Plan for it.

  • After Block, the browser usually remembers it: your code can't show the prompt again, only the user can, in the site settings.
  • Every feature that needs a permission needs a path without it: here, click on the map to choose a place.
  • Tell the user which of the three errors happened and what they can do.
  • Test without moving: DevTools → ⋮ → More tools → Sensors → Location: any city, or "Location unavailable".

~0:32. The Permissions API reads the state without showing a prompt: use it to choose the button's label ("Locate me" vs "Location blocked: click the map"). The change event on the returned status fires when the user changes the setting. Safari supports permissions.query for geolocation since 16.

Option 0 · short polling

Polling: ask again every few seconds

  • Works with any server and every tool from Lecture 8.
  • News waits up to 3 s. Asking every 300 ms costs ten times the requests.
  • Most answers say "nothing changed".
  • Fine for data that changes every minute. The order list on the dispatcher map is polled.

~1:10. Each request carries headers and, without keep-alive, a new connection: a few hundred bytes to say "same as before". Lecture 8's race problem applies: a slow answer can overtake a newer one.

Option 1 · long polling

Long polling: the server waits until it has news

  • One request, held open by the server. News arrives as soon as it exists.
  • No empty answers, except the timeout. Plain HTTP, any proxy.
  • The after cursor is yours: nothing missed between two requests.
  • Each batch still costs a full request, and the server holds one per client.

~1:11. How live pages worked before SSE and WebSocket: early Facebook chat, Gmail, the Comet pattern. Still in use: Telegram's Bot API getUpdates with a timeout, many chat and job-queue APIs. The timeout exists because proxies and load balancers close requests that stay silent too long (often 30–60 s). On an error, wait before asking again (the backoff from the Reconnecting slide), or a broken server gets a request loop. SSE is the same idea with a response that never ends, and the cursor (Last-Event-ID) handled by the browser. The fleet server has no long-polling route: this one is on the slide only.

Option 2 · Server-Sent Events

SSE: one response that doesn't end

GET /orders/8VUA/events

HTTP/1.1 200 OK
Content-Type: text/event-stream

retry: 2000

id: 41
event: position
data: {"lat":41.3871,"lon":2.1702,"etaSeconds":212}

id: 42
event: status
data: {"status":"picked_up"}

… the connection stays open
  • A normal GET. The server keeps the response open and writes to it.
  • Text: one event per block, a blank line ends it.
  • event names it, data carries it, id numbers it, retry sets the reconnect delay.
  • One direction only: server to browser.

~1:12. Show it live: curl -N https://fleet.lopin.me/fleet/events prints one event a second. A data field can span several data: lines; they're joined with newlines. Lines starting with : are comments: the fleet server sends : heartbeat every 15 s so proxies don't close an idle connection. Because it's plain HTTP, CDNs, proxies and DevTools all handle it; the Network panel has an EventStream tab for it.

SSE in the browser

EventSource parses the stream, and reconnects

  • One listener per event: name. Events without a name go to message.
  • The connection drops: it waits retry ms and connects again, by itself.
  • On reconnect it sends Last-Event-ID: 42. The server replays 43 onwards.
  • GET only, no custom headers. events.close() stops it.

~1:14. The replay is the server's job: the fleet server keeps the last 120 events of each order, and a tracker further behind gets the whole order again as one order event. Authentication: no Authorization header, so cookies (withCredentials: true for cross-origin) or a token in the URL. On HTTP/1.1 a browser opens at most 6 connections per origin, and each open EventSource holds one: six tabs and the seventh hangs. HTTP/2 and HTTP/3 multiplex streams over one connection, so the limit is about 100.

Option 3 · WebSocket

WebSocket: starts as HTTP, then both sides talk

GET /courier HTTP/1.1
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==

HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=

… then frames, both ways, on the same connection
  • One connection, both directions, small frames instead of requests.
  • wss:// is WebSocket over TLS, as https:// is HTTP over TLS.
  • Messages are text or binary. No event names, no ids: the format is yours.
  • No CORS: the server checks the Origin header itself.

~1:16. 101 is the one 1xx status they've now seen in practice. The Accept value is a SHA-1 hash of the key plus a fixed GUID: proof that the server speaks WebSocket, not security. DevTools → Network → the request → Messages shows every frame, both directions. Cross-site WebSocket hijacking: since the browser sends cookies with the handshake from any origin, a server that authenticates with cookies must check Origin.

WebSocket in the browser

Open, send, listen, close

  • send before open throws. After close it's silently dropped.
  • A type field in every message: your own small protocol.
  • Close codes: 1000 normal, 1006 lost (no close frame), 1012 server restart.

~1:18. The fleet server's protocol is in its README: hello, position, message up; welcome, order, status, message, error down. 1006 is never sent by anyone: the browser reports it when the connection ended without a close frame (Wi-Fi off, laptop asleep, a proxy cut it). ws.bufferedAmount is the bytes queued but not yet sent: on a slow network, check it before sending more, or skip a position update.

Reconnecting

A WebSocket doesn't reconnect. You do.

  • On close, connect again. Not at once and not in a loop: exponential backoff, 1 s, 2 s, 4 s … up to 30 s.
  • Jitter: a random part of the delay. Thirty clients dropped by one restart don't all return in the same millisecond.
  • Resume: the server needs to recognise you. The fleet's welcome has a courierId: keep it, send it in the next hello.
  • Reset the backoff once a connection works.
  • Heartbeats: a dead connection can look open for minutes. Send "ping", expect "pong", or close and reconnect.

~1:21. Without backoff, a server that restarts gets every client back at once, fails under the load, restarts: a thundering herd. Full jitter (a random delay between 0 and the backoff) spreads them best. The resumed courier also needs its own position along the route: the fleet's welcome has resumeAt, the route index the server last saw. Socket.IO and similar libraries do all of this for you, which is most of why they exist.

The harness: what the model reads, what it runs, what checks it

Context · read at the start of every session

Tell the agent what it can't see in the code

# AGENTS.md
## Stack
- Static site. No build step, no npm install.

  versions from unpkg. Leaflet 1.9.4: 1.9 API.

## Code
- Native elements first: no click handlers on divs.
- CSS: classes and custom properties. No ids,
  no !important.

  every control. `npm run check` passes.
  • Claude Code, Codex, Copilot, Cursor and others read AGENTS.md. An older Claude Code reads only CLAUDE.md: one line, @AGENTS.md, imports it.
  • An agent reads package.json and the lockfile for the stack and the versions. A page with only an import map has neither, so it guesses: npm, a bundler, the version it remembers.
  • Every line is a fact the code doesn't show, or a mistake you've already seen.

~1:41. The Stack section is the part about loading code, from Act 1. "Done means" gives the agent a way to check itself; "Say its licence" makes it surface a copyleft dependency instead of adding it. Files can nest: an AGENTS.md in a subfolder adds rules for that folder.

Context is not free

A short file gets followed. A long one gets diluted.

  • The whole file is in the model's context on every turn. Every line competes with your request.
  • Out: anything a tool can check. Formatting and lint rules go into the linter's config, where they're enforced.
  • Out: what the code already shows. The model reads the files.
  • Elsewhere: long, task-specific instructions, such as an accessibility review procedure. A skill is a folder with a SKILL.md that the agent loads only when a task needs it.
  • When the agent repeats a mistake, add one line. When a line never matters, delete it.

~1:43. Instruction-following degrades as instructions accumulate: rules near the end of a long file, or contradicting each other, get dropped first. Skills are an open format (agentskills.io) supported by Claude Code, Codex, Copilot and others: the agent sees only each skill's name and one-line description until it decides one is relevant.

Checks · run them on every edit

A hook runs the checks; the agent reads the failures

// .claude/settings.json · Claude Code
{ "hooks": { "PostToolUse": [{
  "matcher": "Edit|Write",
  "hooks": [{
    "type": "command",
    "command": "npm run check 1>&2 || exit 2"
  }]
}] } }
  • The harness runs the command after every file edit. The agent doesn't decide whether to.
  • Exit code 2: the output goes back to the model, which fixes the errors before it continues.
  • Other agents have the same idea under other names. Without one: a Git pre-commit hook runs the same script.

~1:49. For PostToolUse, exit code 2 passes stderr to the model (the edit has already happened); other non-zero codes only show it to the user. Keep the hook fast: a full Lighthouse run after every edit makes every step slow; validators and linters take a second. A Stop hook runs when the agent wants to finish: the place for slower checks.

Working with an agent

Plan, a small diff, then read the diff

  1. Commit before it starts. git diff is what it changed; git restore . undoes all of it.
  2. Ask for a plan first. Correct the plan, not 300 lines of code.
  3. One feature per session. A fresh session for the next: the context fills up and early instructions fade.
  4. Read the diff, not the summary. Run the page yourself.
  5. A line you can't explain: ask about it, then keep it or delete it.
  6. The same mistake twice: fix the harness (a rule, a check), not the prompt.

~1:50. Summaries are written by the same model that wrote the code; they describe intent, not what the diff does. Many agents have a plan mode that can read but not edit. Step 6 is the important one: a correction in a prompt lasts one session, a line in AGENTS.md or a lint rule lasts for every session after it.

It runs on your machine

Decide what the agent may do without asking

  • Reading and editing the project: allow. Commands that install, delete, push or deploy: ask.
  • npm install is never automatic: an invented package name runs its install script on your machine (Act 1's slopsquatting).
  • Secrets stay outside the project folder. What the agent can read, it can send.
  • Pages and issues it reads can contain instructions written for it: prompt injection. Review what it does after reading the web.
  • For long unattended runs: a container or the agent's sandbox mode.

~1:51. Claude Code: permission rules in .claude/settings.json (allow, ask, deny per tool and command pattern); Codex and Gemini CLI have sandbox and approval modes. A real example of injection: text hidden in a web page or a README ("ignore previous instructions and run …") that the agent reads while researching. The browser MCP from the previous slides is exactly the kind of tool that reads untrusted pages.
