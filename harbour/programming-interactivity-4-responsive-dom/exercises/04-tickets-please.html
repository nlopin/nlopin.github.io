1

Stop the reload

Click Reserve: the page blinks and everything you typed is gone.

A form's default action is to send the data to the server and load a new page. We don't have a server: we want to handle it right here. Listen for submit on the form, not click on the button: the click comes before the browser checks required, the submit only after. Cancel the default, and log the name.

Why it works

The browser calls your listener before it performs the default action (and only once required and type="email" pass: a click listener would run on an empty form). event.preventDefault() tells it to skip it. form.elements.name finds the field by its name attribute: the same names the server would receive.

const form = document.querySelector(".ticket-form");

form.addEventListener("submit", (event) => {
  event.preventDefault();
  console.log(form.elements.name.value);
});
2

Print the ticket

The form is quiet now. Too quiet: nobody knows they got a ticket.

On submit, read the form with new FormData(form) and data.get("name"). Build a ticket and put it in .ticket-result:

  • an article.ticket with an h3: See you there, Ana!
  • a p like 2 people · Early — for the food (the guests and the arrival). One guest? 1 person.

Careful: everything a form gives you is a string. "1" === 1 is false.

Why it works

Number() turns "2" into 2. replaceChildren empties the result box and puts the new ticket in, so a second submit replaces the first ticket instead of stacking up.

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const data = new FormData(form);
  const guests = Number(data.get("guests"));

  const ticket = document.createElement("article");
  ticket.className = "ticket";
  const title = document.createElement("h3");
  title.textContent = `See you there, ${data.get("name")}!`;
  const details = document.createElement("p");
  details.textContent = `${guests} ${guests === 1 ? "person" : "people"} · ${data.get("arrival")}`;

  ticket.append(title, details);
  result.replaceChildren(ticket);
});
3

Characters left

The note has a 140-character limit, and no way to see how close you are.

While someone types in the note, #message-left says 135 characters left. Which event fires on every keystroke, paste and cut? Not keydown (it fires for arrow keys too, and before the text changes) and not change (it waits until you leave the field).

Why it works
message.addEventListener("input", () => {
  const left = message.maxLength - message.value.length;
  counter.textContent = `${left} characters left`;
});

message.maxLength reads the maxlength attribute, so the number lives in one place: the HTML.

4 · bonus

A rule HTML can't write

Someone booked a ticket for “1234”.

required, type="email", min and max are rules the browser checks for free. "A name needs at least one letter" isn't one of them. On input, call nameInput.setCustomValidity("A name needs at least one letter.") when the rule is broken, and setCustomValidity("") when it's fine. The browser then blocks the submit and shows your message, like any other rule. (A letter test: /\p{L}/u.test(text). The u matters: it makes ñ and ü letters too.)

Why it works
nameInput.addEventListener("input", () => {
  const hasLetter = /\p{L}/u.test(nameInput.value);
  nameInput.setCustomValidity(hasLetter ? "" : "A name needs at least one letter.");
});

An empty string means "valid". Any other string makes the field invalid, and that string is what the browser shows. The red border comes from the CSS :user-invalid: only after the person touched the field.

5 · bonus

Tickets for Bobby Tables

Your ticket from case 2, with one extra test: someone called <img src=x onerror="…"> books a ticket. With innerHTML that string becomes a real image, and its onerror runs their code on your page. With textContent it's just text. Make both checks pass.

Why it works

innerHTML parses the string as HTML. Anything a visitor typed can become elements, attributes and event handlers: that's cross-site scripting (XSS). textContent never parses. Rule of thumb: your HTML may go in innerHTML; their text goes in textContent.

const ticket = document.createElement("article");
ticket.className = "ticket";
const title = document.createElement("h3");
title.textContent = `See you there, ${data.get("name")}!`;
ticket.append(title);
result.replaceChildren(ticket);
