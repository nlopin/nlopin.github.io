Act 1 · Small screens

Pocket check

The market page, one phone problem at a time. Every editor has a window-width slider and three presets (📱 360 · ▭ 800 · 🖥 1200). The checks test every width at once, so a fix for the phone that breaks the laptop doesn't pass. A red 🦝 means something makes the page scroll sideways.

Mobile first. Rules outside any @media are for the phone. Wider screens get extras, in @media (width >= …). Breakpoints come from where your content breaks: drag the slider until it looks wrong. Use rem, not device names.

0

First, the real phone

On my phone the market is a tiny desktop page. I have to pinch to read anything.

This one happens in your project, not on this page (a live editor can't fake a phone's browser).

  1. Open your copy of 04-responsive-dom/project/starter/index.html. In DevTools, turn on the device toolbar (⌘ ⇧ M / Ctrl ⇧ M) and pick a phone. Tiny, right? That's the browser pretending to be 980px wide.
  2. Add the missing line to the <head>: <meta name="viewport" content="width=device-width, initial-scale=1">. Reload. Now the page is as wide as the phone, and it breaks honestly: that's what cases 1–3 fix.
  3. Optional, 1 minute: start your server with npx live-server, find the Network address it prints (like http://192.168.1.23:8080) and open it on your phone, on the same Wi-Fi.

The menu runs off the screen

On a phone the menu runs off the right edge, and the whole page wobbles sideways.

This is last time's header. Drag the width to 360px (or press 📱): the red 🦝 marks the element sticking out. Keep the logo and the links on one line on wide screens, and let them wrap on narrow ones. No media query needed.

Why it works

A flex line never breaks unless you let it: flex-wrap: wrap. On the header, the nav drops under the logo when they don't fit side by side; on the list, the links wrap onto a second line. A row-gap keeps the lines apart. The layout adapts without asking the window anything.

.site-header {
  display: flex;
  flex-wrap: wrap;
  justify-content: space-between;
  align-items: center;
  gap: 0.5rem 1.5rem;
}
.main-nav ul {
  display: flex;
  flex-wrap: wrap;
  gap: 0.25rem 1.5rem;
}

The featured stall

On a phone the featured card forces a second column. Everything is squeezed, then the page scrolls sideways.

Mobile first: the phone is the default, and the extra (spanning two columns) is only switched on where there's room for it. Wrap the .featured rule in a min-width media query. Where should the breakpoint be? Drag the slider and find the width where two columns first fit.

Why it works

Outside any @media: the phone. Inside @media (width >= 34rem): things that only make sense with room. Why about 34rem? Two 15rem columns + a 1rem gap + 2rem of body padding = 33rem, plus a little slack so the cards don't sit at their exact minimum. You'd find it by dragging, not from a list of iPhone sizes. (width >= 34rem) is the newer range syntax; (min-width: 34rem) means the same and works in older browsers too.

.featured {
  /* nothing: on a phone it's a card like any other */
}
@media (width >= 34rem) {
  .featured {
    grid-column: span 2;
  }
}

Redraw the map for big screens

The phone map is fine. On a laptop it's a tall, narrow tower.

The phone map is already in the stylesheet (read-only). Inside a media query, redraw it for wide windows: three columns, 1fr 2fr 1fr, following the floor plan in the comment. Only the drawing changes; the HTML order never does.

Why it works

Inside the query you only override what changes: the columns and the areas. Everything else (the gap, the row height, each zone's grid-area) carries on from the phone rules.

@media (width >= 50rem) {
  .market-map {
    grid-template-columns: 1fr 2fr 1fr;
    grid-template-areas:
      "stage  stage  pier"
      "food   table  pier"
      "food   crafts drinks"
      "gate   gate   gate";
  }
}

Not every query is about width

On my phone, a card I tapped stays lifted. And my friend with motion sickness says the page scrolls “like a rollercoaster”.

Phones have no hover: after a tap, :hover sticks. Put the lift inside @media (hover: hover). And some people ask their system for less motion: only turn on smooth scrolling inside @media (prefers-reduced-motion: no-preference).

Why it works

Try them without changing your settings: DevTools → ⋮ → More tools → Rendering → Emulate CSS media feature prefers-reduced-motion. The same panel emulates prefers-color-scheme and print.

@media (hover: hover) {
  .vendor-card:hover {
    translate: 0 -6px;
    border-color: #5ec8d8;
  }
}
@media (prefers-reduced-motion: no-preference) {
  html {
    scroll-behavior: smooth;
  }
}
5 · bonus

One variable, every breakpoint

The spacing is hard-coded in three places. Make a custom property --gutter on :root: 1rem on phones, 2.5rem from 50rem up. Use it for the body padding and the list gap. The media query changes one variable; everything that uses it follows.

Solution

Custom properties are real, live values in the cascade: redefine one inside a media query and every var() that reads it updates. One limitation: you can't use var() in the query itself: @media (width >= var(--bp)) doesn't work.

:root { --gutter: 1rem; }
@media (width >= 50rem) {
  :root { --gutter: 2.5rem; }
}
body { padding: var(--gutter); }
.vendor-list { gap: var(--gutter); }
