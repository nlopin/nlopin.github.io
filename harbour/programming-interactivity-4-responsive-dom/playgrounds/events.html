Events

Who hears the click?

Click a ♡ button. The click starts at the button (event.target) and bubbles up through every ancestor. Each ancestor with a listener hears it, in order: at that moment it's the event.currentTarget. Switch listeners on and off, stop the bubbling, and turn on closest("li") to see how one listener on the list can serve every stall.

Which events, in which order?

Use the form. Every event it fires is logged in order. Watch the difference between keydown (a key went down: fires for arrows and Shift too), input (the value changed) and change (the value changed and you're done: you left the field, picked an option, ticked a box). Then press Enter inside the name field.

Try this

  1. Listeners on button and ul. Click a ♡: two lines. Click the stall's name instead: who hears it now?
  2. Add stopPropagation() in li. Which listeners go deaf?
  3. Only ul listening, closest("li") on. Click different parts of each stall. That's event delegation: one listener, many stalls.
  4. In the form: type a name, then press Tab. Which event fires only now?
  5. Press Enter in the name field. Which event fires, even though you never touched the button?
