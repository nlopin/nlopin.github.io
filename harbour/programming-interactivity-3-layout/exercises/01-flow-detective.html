Act 1 · Flow

Flow detective

Before we leave normal flow, we fix it. Each case is a real bug from the market page. Predict what's wrong before you touch the code, then fix it in the editor. The chips turn green when the case is closed. The index.html tab above each editor shows the HTML, with every class name. Cases 1–4 in class; 5–7 if you finish early (6 is the warm-up's cascade fight).

Two rules you need today. In flow, a block's width comes from its parent (it fills the line), and its height comes from its children (it grows with its content). Every case below is one of those two rules, the box model, intrinsic sizing, or the cascade.

1

The inputs that stick out

The name and email boxes stick out of the ticket form on the right.

Both inputs have width: 100%. So why are they wider than the form?

Why it works

By default width sets only the content. Padding and border are added on top: 100% + 2 × 0.9rem + 2 × 2px. box-sizing: border-box makes width mean the whole visible box. Put it on everything, once, at the top of every stylesheet:

*, *::before, *::after { box-sizing: border-box; }
2

Wall to wall

On a big monitor the text runs from one edge of the screen to the other. Nobody reads lines that long.

Make main at most 36rem wide and put it in the middle of the window. Drag the window-width slider to test a big and a small screen.

Why it works

A block is as wide as its parent allows. max-width caps it, and the space that's left over has to go somewhere: an auto margin eats it. Auto on both sides = equal halves = centred. Use max-width, not width: on a phone narrower than 36rem, it still shrinks.

main {
  max-width: 36rem;
  margin-inline: auto;
}
3

The hero that won't grow

The hero should fill the whole first screen.

Someone already wrote height: 100%. It does nothing. Why? Make the hero at least as tall as the window, without a fixed number of pixels.

Why it works

Width flows down from the parent, but height grows up from the children. height: 100% means "100% of my parent's height", and the parent's height is auto: it waits for its children. Nobody knows the number, so the browser ignores the percentage. vh is measured from the window, which always has a height. Use min-height, so the hero can still grow when the text is longer than the screen.

.hero { min-height: 100vh; }
4

The missing 20 pixels

30px of margin under the first card, 20px above the second. The gap is 30px, not 50px.

Measure the gap (the blue labels show every box). Then make it exactly 50px. You may not change .a.

Why it works

Vertical margins between blocks collapse: they don't add up, the bigger one wins. 30 and 20 → 30. So .b needs margin-top: 50px (50 beats 30). Horizontal margins never collapse, and neither do margins inside a flex or grid container. That's one reason people like gap.

.b { margin-top: 50px; }
5 · bonus

The button that ignores its width

The ticket button should be 12rem wide. It isn't, and its padding covers the line above.

Don't touch the width. Find the one declaration that lets width and vertical padding work, while the button stays inside the sentence.

Why it works

a is an inline box: it flows like a word, and words have no width. Its vertical padding is painted, but doesn't push the lines apart. inline-block sits in the line like a word, but is sized like a block.

.button {
  width: 12rem;
  text-align: center;
  display: inline-block;
}
6 · bonus

The rule that loses

.card { max-width: none } is in the stylesheet, yet the card is still narrow. Is the browser broken?

Make the card as wide as its section. No ids, no !important. Check DevTools in your head first: which rule is crossed out, and why?

Why it works

main section .card scores (0,1,2). .card scores (0,1,0) and loses, even though it comes later. Match it (a tie, and yours comes later) or beat it, for example with main section .card or section .vendor-card.card. Layout properties are ordinary properties: display, width, position all go through the same cascade.

main section .card { max-width: none; }
7 · bonus

The tag that stretches

The tag must sit on its own line (so it stays display: block), but only be as wide as its text. No inline-block, no flex, no fixed width.

Why it works

width: fit-content asks for the intrinsic size: max-content, capped by the available space. max-content also passes here (but never wraps). This is the width absolute boxes and floats get automatically.

.tag {
  display: block;
  width: fit-content;
}
