Stored XSS

Harbour guestbook

⚠ Intentionally vulnerable — teaching demo.

In vulnerable mode this guestbook stores each message in localStorage and renders it with innerHTML, with no escaping. A message is saved, so any markup in it runs for every visitor, on every load: that's stored (persistent) XSS, worse than the reflected kind. Switch to safe mode to see the same posts rendered with textContent. Don't ship this pattern.

Rendering:

    Side effects on this page

    None yet. Injected code that runs will announce itself here.

    Try it

    1. In vulnerable mode, post a normal message. It appears. Reload: still there (it's in localStorage).
    2. Post <img src=x onerror="xssRan('image handler')">. It runs immediately, and again on every reload, because it's saved.
    3. Post <b style="color:#ff6b5a">defaced</b>: stored markup changes the page for anyone who opens it.
    4. Switch to safe mode and reload. The same stored messages now show as plain text: innerHTML was the bug, not the data.
    5. A real payload wouldn't call a demo function; it would read a session cookie or token and send it to another origin. The XSS lab shows that part safely.

    The fix

    • Render user content with textContent (or a <template> + textContent, like today's card()), never innerHTML.
    • If you genuinely need to render HTML from users, sanitise it (DOMPurify, or element.setHTML() where supported) — never a regex, and never a <script> blocklist.
    • Defence in depth: a Content-Security-Policy header, and session cookies marked HttpOnly so JavaScript can't read them.
