Jam · task 1 · fix it

Theremin · fix it

Someone has already built <theremin-pad>. It runs, and it's nearly right: three bugs stand between it and the brief. Find them, fix them, then make the tag yours.

The tag, its public API and its gates are the ones in the main brief. APIs: Web Audio API · Pointer Events · Canvas

Start

⤓ Download the broken tag

The zip holds a theremin-pad/ folder: theremin-pad.js and the index.html it runs in. Serve the folder (npx live-server): camera, microphone and the clipboard need localhost or HTTPS. Keep a copy of the broken version: on stage you show one bug before and after.

What the users report

Each report is one bug. Fixing one can make another easier to see.

  • No sound at all, from the very first press. The console has a warning about the AudioContext.
  • The picture is squashed: the circle under your finger is a flat oval, and the Hz readout is stretched wide and flat.
  • After the first note, choosing another wave in the page's menu doesn't change the sound.

Where to look

  • Console: errors and warnings, with the line that threw them.
  • Sources: a breakpoint (or debugger;) in the handler you suspect, then step through.
  • Console: monitorEvents(document.querySelector("theremin-pad")) logs every event the element receives; unmonitorEvents stops it.
  • Elements: attributes update live, and the shadow root is open.

Done means

  • Every report above is gone, and nothing else broke: run the checks in the main brief.
  • For each bug you can say three things: the symptom, the cause, the fix. Write them in a comment next to the fix.

Done means · the tag contract

Most of the bugs break one of these.

  • One file, one element: theremin-pad.js defines <theremin-pad> and nothing else. Drop the file into any page and the tag works.
  • Attributes configure, properties carry data, events report: events bubble (bubbles: true), and the page never reaches into your shadow root.
  • Passes its gates in order: nothing starts before a user gesture; if it needs a permission, it reads the state first and asks only after the user asks for the feature.
  • Handles no: a refusal, a missing API or a missing device shows visible content that says what to do; a permission revoked while running is noticed.
  • Releases everything in disconnectedCallback: tracks, AudioContext, animation frames, timers, listeners on window.

Then, if there's time

  • Snap to the notes of a scale, with an attribute to choose the scale.
  • Two fingers, two voices.
  • A record method and a loop event.

Stuck? One hint at a time

Hint 1

When is the AudioContext created, and what is its state at that moment?

Hint 2

A canvas has two sizes: the one it takes on the page, and its width and height attributes. Compare them in the console.

Hint 3

Which attribute changes does the element ask the browser to report?
