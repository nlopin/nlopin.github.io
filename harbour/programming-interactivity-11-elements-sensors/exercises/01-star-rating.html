Act 1 · your own tags

Exercise 1 · After the call

The call has ended, and Parley asks the question every call app asks: how was the call quality? Today the answer is an <input type="number">. Replace it with a tag HTML doesn't have, one that the form treats like any of its own controls.

<star-rating id="quality" name="quality" max="5" required></star-rating>

Start

⤓ Download the starter
  • Extract the zip and serve the folder from a local server: module scripts need http://, not file://.
cd 01-star-rating
npx live-server --port=8080
  • index.html: the post-call form. The comment in it shows where your tag goes.
  • star-rating.js: an empty class and the define call. Your element goes here.
  • main.js: the app. On submit it prints what FormData holds; it logs every change event that reaches the form. You shouldn't need to change it.

Done means (18 minutes)

  • The form prints "quality": "4" after you pick four stars, and nothing for quality before you pick any.
  • With required, Send does nothing until a rating is chosen, and the browser shows its own validation message next to the stars. Clear empties the rating.
  • main.js logs change from star-rating when the rating changes, and not when it stays the same.

Then, if there's time

  • Tab reaches the stars once, and the arrow keys change the rating. Clicking the label focuses the stars. The green room's picker (08-keyboard/device-picker.js) solves the same problem for a list: read it for the pattern.
  • Add span { color: red; padding: 8px; } to style.css: your stars don't change, and your element's own styles don't change the page.
  • The app's dark theme recolours the stars without editing star-rating.js: decide what your element exposes for that.
  • max="10" in the markup gives ten stars.

Check it

  • Console: document.querySelector("star-rating").value = 2. Does the display follow? Does FormData?
  • Unplug the mouse. Fill in and send the whole form from the keyboard.
  • DevTools → Elements → Accessibility pane on one star: what role and name does it have? What would a screen reader say?
  • Console: document.createElement("star-rating"). Any error? Append it to the form: does it work?
  • Load the element two seconds late: replace its script tag with <script type="module">setTimeout(() => import("./star-rating.js"), 2000)</script>. What does the form show for those two seconds, and does the element work after?

Stretch

  • A readonly attribute: shows the rating, can't be changed, still submitted.
  • Hovering previews the rating without changing it.
  • A custom state, so the page can style a rated element with star-rating:state(rated).
  • Navigate away and press Back: does the browser restore the rating? Look up formStateRestoreCallback.
  • The first render without JavaScript: declarative shadow DOM in the markup, upgraded when the script arrives.

Stuck? One hint at a time

Hint 1

What does the form ask a native control for? Which object gives a custom element the same voice?

Hint 2

Where does the browser look for the validation message and for the element that should get focus when the form is invalid?

Hint 3

Which method does a form call on its controls when it resets?

Hint 4

How many elements should be in the Tab order for one group of choices? What does the WAI-ARIA radio group pattern say?

Hint 5

An event dispatched from inside a shadow root and one dispatched on the host: which options does each need to reach the form?

Traps

Open when something behaves strangely
  • Your element is never in FormData, even with a value set.
  • Send is blocked but no message appears, and the console says the control "is not focusable".
  • Failed to execute 'createElement' on 'Document': The result must not have attributes (or children), and the element you get back does nothing.
  • NotSupportedError: … has already been used with this registry.
  • The arrow keys scroll the page as well as changing the rating.
  • After a re-render, keyboard focus jumps to the top of the page.
