Act 4 · engineering an explorable

Exercise 3 · Build three frames

Build frames 2, 3 and 4 of your storyboard: the first touch, the second control, the surprise. Plain HTML, CSS and JavaScript. The drawing can be rough; the order of revelation can't.

Start (pick one)

⤓ Explorable starter ⤓ Playground starter
  • Explorable starter: main.js has three steps, one per frame, a state, a figure drawn from the state, a sentence describing the state, and inputs bound to it. model.js is where the idea's computation goes, with no DOM, and claims.test.mjs checks the surprise you promise (node --test claims.test.mjs). Replace the TODOs. rng.js is a seeded random generator, if your surprise needs randomness.
  • Playground starter, if your idea is about code (sort(), 0.1 + 0.2, Intl): replace STARTER and EXPECTED at the top of playground.js, and the challenges in index.html.
  • Serve the folder over http://: npx live-server --port=8080. Module scripts don't load from file://.
  • Reference: the token bucket, built in seven steps, in demos/token-bucket.

Done means, on the explorable track (33 minutes)

  • The first screen asks your question and offers exactly one thing to touch.
  • Something visible changes within a second of the first touch.
  • The second control appears only at the second step, and the text says why it appears now ("But …" or "Therefore …").
  • The surprise happens on every load, from the defaults of that step.
  • A sentence under the figure says what the figure shows, and changes with it.

Done means, on the playground track

  • The starter runs and shows the problem in its output; one marked place (// ✎) is the first thing to change.
  • The first challenge's EXPECTED checks fail on the starter and pass after the one edit.
  • A second challenge asks the reader to predict first, and its text says why it comes now ("But …" / "Therefore …").
  • The surprise is in the output, not in the answer box.

Test it (last 7 minutes)

Give your laptop to your neighbour. Don't speak, don't point, don't touch the mouse. Write three things, then swap:

  • Where did they hesitate? (Which step, which control.)
  • Did they reach the surprise without help: yes or no?
  • The sentence you wanted to say. That sentence is missing from the page.

Then, if there's time

  • Frame 5: the rule, stated in a sentence, after the surprise.
  • Frame 6: a sandbox with every control, or a question to end on.
  • The state in the URL, so a link opens your surprise.
  • Every number your text states is a test in claims.test.mjs.
  • Every control works from the keyboard. Try it with the mouse unplugged.

Stuck? One hint at a time

Hint 1 · I don't know how to draw it

Draw the fewest marks that show the state: bars, dots, a line. The starter draws two bars. Polish comes after the surprise works.

Hint 2 · the surprise doesn't happen

Which value of which control makes it happen? Put that value in the step's set, so the reader starts there, one move away from it.

Hint 3 · my idea needs too many controls

Which one control shows the idea on its own? Fix all the others in set and leave them out of controls.

Hint 4 · my idea is about code

Use the playground starter. The reader's first touch is one edit to one line; mark that line with a comment.

Traps

Open when something behaves strangely
  • The page is blank and the console says the module was blocked: you opened the file from disk. Serve it.
  • Moving a slider does nothing: the input changes the state but nothing calls render().
  • A slider jumps back when the step changes: that's goTo() resetting the state to the step's set. Intended.
  • The playground prints "Stopped: still running after 1.5 s": the code has an infinite loop, and the watchdog threw its frame away. Fix the loop; the next edit runs in a fresh frame.
  • Your surprise only happens on some loads: it depends on random data. Seed it (rng.js) and write the seed into the step's set.
