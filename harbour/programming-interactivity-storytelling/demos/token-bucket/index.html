A token bucket, step by step

One explorable, built in seven complete folders. Each folder runs on its own; open two side by side and diff them to see one technique at a time. No libraries, no build step. Serve the folder over http:// (module scripts don't load from file://).

  1. 01 · one state, three views: simulate() is a pure function; the bucket, the timeline and a sentence are all rendered from one state. A slider moves time.
  2. 02 · inputs bound to state: sliders for capacity and rate; click, drag and remove requests on the timeline with Pointer Events and setPointerCapture; or focus a request and use the arrow keys and Delete (edit.js, shared by every later step).
  3. 03 · a stepper: the explanation as data (steps.js). Each step sets the figure's starting state and lists the controls the reader has. Predict, then reveal. Back works.
  4. 04 · scroll-driven: the same steps; an IntersectionObserver picks the step, position: sticky keeps the figure in view. The steps after the question stay hidden until the reader answers it.
  5. 05 · seeded randomness (from 02): random traffic from mulberry32(seed). Same seed, same bursts, for every reader.
  6. 06 · state in the URL (from 05): the query string follows the state; links in the text open a given state; Back returns to the previous one. Values from the URL are validated.
  7. 07 · time you can pause (from 06): a requestAnimationFrame loop with play, pause and step; paused at load under prefers-reduced-motion.

Shared by every step: model.js (the bucket, no DOM) and views.js (three render functions, no state, and announce() for screen readers).

Every number the explanation states is a test: node --test test/claims.test.mjs in this folder.
