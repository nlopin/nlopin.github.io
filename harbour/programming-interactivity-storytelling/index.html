Let them touch it

How a page explains an idea by letting the reader touch it. What good explorable explanations have in common: a question first, one concrete case before the rule, beats joined by "but" and "therefore", one control at a time, a sandbox at the end. Then code playgrounds, where the control is code. Then the engineering underneath: one state and several views, steps as data, scroll, seeded randomness, state in the URL, time you can pause. Then showing working code to a room.

Exercises

  • Exercise 1 · Take one apart: ten explorable explanations, one per group, and a card of nine questions about the author's decisions. Groups of 3, 20 min. Printable card.
  • Exercise 2 · Six frames: storyboard one idea on paper, then swap and critique. 14 min. Printable sheet, a filled-in example.
  • Exercise 3 · Build three frames: the first touch, the second control, the surprise. An explorable starter and a playground starter. 40 min, including the silent test.

Demos

  • A token bucket, in seven complete folders: two views, inputs, a stepper, scroll-driven, seeded, state in the URL, time. Every number its text states is checked by test/claims.test.mjs.
  • Whose 09:00? A playground for Intl time zones: a textarea, a fresh sandboxed iframe per run with a watchdog, a console that shows values, reset, the code in the URL, checks, predict-first challenges.
  • The token bucket, outlined twice: "and then" vs "but / therefore".
